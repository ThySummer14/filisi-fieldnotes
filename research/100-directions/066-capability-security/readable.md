# 给图片解码器一张照片 不必给它整个相册

一个工具只需把用户选中的照片转成缩略图。如果它继承用户账户全部文件权限，解码一张照片的代码同时可能读取其他目录。文件格式解析器一旦出错，风险就超出了当前照片。更窄的设计，是只交给它读取这份输入和写出指定结果的能力。

能力式权限中的capability通常是不可伪造的权限引用，指向特定资源及允许操作。知道一个文件路径，与持有能读这个文件的句柄，不是同一件事。路径可以猜到，权限引用需要由已有权利的一方授予或传递。

[Capsicum原始论文](https://www.usenix.org/legacy/event/sec10/tech/full_papers/Watson.pdf)讨论如何在UNIX环境中用细化文件描述符和能力模式支持权限分隔，并区分针对具体对象的能力与某些操作系统里同名的广义特权。词叫capability，不意味着模型都一样，阅读接口时应看它究竟授予什么。

## 权限可以随着参数一起走

传统接口可能接受一个任意路径，再以服务进程自己的广泛权限打开文件。调用者提供了名字，服务却提供了力量；如果两者的授权边界没有对应起来，就可能出现服务替调用者做了超出其权限的事。

若接口直接接受受限制的文件句柄，调用方交付的是已经选定的对象及权限。缩略图函数不必再拥有遍历整个文件系统的能力。这个结构减少了环境中默认可用的权力，也让测试更容易观察：不给目录句柄，它是否仍能完成指定工作？

[WASI的能力设计文档](https://github.com/WebAssembly/WASI/blob/main/docs/Capabilities.md)区分链接时能力和运行时能力。前者可以是实例化时提供的函数接口，后者是运行中传递的资源句柄。WebAssembly本身没有内建系统调用和I/O入口，外部交互需要宿主提供，因此宿主提供的接口就是重要边界。

把文件访问换成一个万能的“执行任意命令”导入，并没有实现最小权限。接口数量很少，能力却可能极宽。应该按能造成的效果判断范围，而不是按API有几个函数判断。一个网络发送接口也可能使已读取的照片离开本机，读权限与外传路径要一起考虑。

## 用户挑选对象 是一次具体授权

浏览器的文件选择器提供一种面向用户的对象选择流程。[Chrome的File System Access说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)介绍由用户选择文件或目录后获得句柄，并分别处理读取与写入权限。用户选择一份文档编辑，不必等同于允许站点遍历所有本地文件。

目录授权比单文件授权范围更大。批量整理照片可能确实需要目录，但只制作一张缩略图时没有必要默认扩大。产品应解释为什么需要整个目录，提供较窄的可行路径，并让用户能在之后检查和撤回访问。方便不应来自把本次操作偷偷变成长期全盘权限。

[File System Access规范](https://wicg.github.io/file-system-access/)定义read与readwrite等权限模式，也包含查询和请求权限的过程。持有旧句柄不等于当前一定仍获授权；浏览器或用户可能改变权限状态。应用应处理拒绝与失效，而非把重新授权当成必然成功的后台步骤。

这里的浏览器机制并非对纯对象能力系统所有性质的完整实现。它仍受浏览器权限模型、来源隔离和用户激活等规则约束。把它作为范围明确的文件访问例子很有用，但不能据此推断任何网页句柄都能任意转交或永久保存权限。

## 撤销只能阻止未来的使用

如果解码器已经把照片字节复制到内存，撤销原文件句柄不会让这份副本自动消失。若它已经通过允许的网络接口发走数据，之后关闭读取权限更无法追回。撤销的语义需要明确：阻止下一次读取、终止当前任务，还是清理已产生副本，这些是不同动作。

能力可以经由代理间接提供，以便集中检查额度、时间或撤销状态。代价是每次使用可能依赖代理，代理本身也必须正确实现检查。若直接把底层永久句柄交出去，再把代理关掉，已经交出的能力未必随之失效。设计撤销时要沿着实际授权链查看，而非只删除界面上的一行记录。

同样，降低权限不应允许反向扩大。Capsicum论文中的能力派生要求权利是已有权利的子集。这种限制让一个只读处理阶段无法自行升级为可写。具体实现还要覆盖元数据操作与目录查找等入口，不能只禁止最显眼的write调用。

## 最小权限也需要任务边界

图片解码器只需要输入字节和输出缓冲，缩略图保存组件需要目标位置写入，界面组件需要向用户报告结果。拆开后，每部分可获得不同权限。拆分也有通信和维护成本，不必把每个小函数都变成独立沙箱；优先隔离处理不可信输入、又不需要广泛权限的部分。

没有权限不代表没有资源风险。一个受限解码器仍可能消耗大量CPU或内存，需要资源上限与超时。能力范围控制能碰哪些对象，资源管理控制能用多少，二者互相补充。安全边界还依赖宿主、内核和接口实现，不能仅凭架构图宣布代码漏洞无害。

在这张照片的流程里，可以让解码阶段完全不知道相册目录在哪里，只接收已选照片的读取能力。保存阶段收到一个明确目标，写完即结束。若用户之后选择另一张照片，再提供新的对象。授权随任务具体化，程序就不必先拥有整间房子的钥匙，才能处理桌上的一张图片。
