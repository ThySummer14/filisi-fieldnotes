# 地上有一条缝 角色却没有一条路

两堵平行墙之间留出一米宽的通道。一个半径0.6米的圆形角色中心看起来有路可走，身体却会同时碰到两边；半径0.4米的角色则在理想平面几何中留下0.2米宽的中心活动带。屏幕上的空地相同，角色尺寸改变了可行空间。

这个计算只是通道宽度减去两倍半径，忽略墙体误差、离散化与碰撞余量。它已经说明，导航网格不能只回答“地板上哪里没有墙”，还需要回答“这个角色的参考点放在哪里，整个身体不会撞墙”。

## 让障碍长大 让角色变成点

LaValle的[Planning Algorithms配置空间章节](https://lavalle.pl/planning/node161.html)解释了将刚体平移问题转换为配置空间障碍的方法。对圆形平移角色，可以直观地把障碍向外扩张相应半径，再让角色中心作为点移动。更一般形状需要按反射后的角色形状构造Minkowski和，不能一律用圆圈替代。

这个转换把尺寸条件移进地图。于是网格边缘离墙留有距离，并不是浪费可走区域，而是在为角色身体预留空间。如果把同一张为小角色烘焙的网格直接交给大角色，路径算法仍可能返回一条漂亮路线，碰撞系统却会在门口把它挡住。

[Godot NavigationPolygon文档](https://docs.godotengine.org/en/stable/classes/class_navigationpolygon.html)将agent_radius定义为烘焙时收缩可走表面的距离。这是导航几何中的参数，不能与运行时避障半径随意混同。一个负责静态可达区域，另一个可能影响移动中的相互避让，修改后者未必会重新打开被烘焙封住的门。

## 半径之外 还有头顶和脚下

[Recast接口文档](https://recastnav.com/group__recast.html)展示了栅格化、可行走坡度标记、净空过滤与可走区域侵蚀等步骤。地面三角形角度太陡、上方净空不足、台阶超过允许高度，都可能使视觉上连续的地面在导航表示中断开。

因此，角色钻不过一座拱门，未必是路径搜索失败。可能是烘焙高度太大，也可能是碰撞几何与渲染几何不同。一个只显示彩色导航面、不显示角色碰撞体的调试视图，容易让人把这几种问题混在一起。应把实际参与烘焙的几何、角色半径高度与生成结果叠在一起看。

移动能力也不全是尺寸。能跳的角色可以跨越缺口，会攀爬的角色可以连接不同楼层；常规地面网格通常需要额外链接表达这些动作。链接是否双向、是否有进入条件、执行期间能否中断，都属于路线可执行性的约束。图上连了一条边，不会自动生成角色该如何跳过去的动画与碰撞处理。

## 分辨率会吞掉窄路

导航烘焙常把连续几何离散到体素或栅格。[Unity NavMeshSurface文档](https://docs.unity3d.com/Packages/com.unity.ai.navigation@2.0/manual/NavMeshSurface.html)提供体素尺寸等构建设置。粗网格能减少计算与数据量，却可能丢失狭窄通道和细小台阶；细网格保留更多细节，也增加烘焙成本。

这使前面0.2米的理想活动带并不保证在实际烘焙后仍存在。侵蚀半径的离散换算、边界简化和安全余量，都可能进一步收缩它。不能把几何宽度刚好大于直径当作稳定通行条件，尤其在拐角和倾斜墙面附近。

若一个关卡依赖角色恰好挤过门，应该在目标烘焙设置下验证，并给误差留空间。为了救一条窄路而把半径调得比真实碰撞体还小，会让导航宣布更多不可能路径；局部看起来修好了，其他墙角却可能开始卡住。应先确认美术尺度、碰撞尺度和导航尺度使用了同一单位。

## 路线存在 不等于现在走得过去

静态网格连接两点，只说明在所建模的环境中存在路线。其他角色临时堵门、动态箱子挡路或门状态变化，可能使当前路径不可执行。局部避障可以调整速度避免碰撞，却不一定能发现一个需要绕到另一条走廊的全局替代路线。

重烘焙、动态切割、局部路径重算和避障各处理不同层次。给移动障碍开了避障功能，不代表导航拓扑已经更新；把障碍切进网格，也不等于角色控制器会自动等待开门。排查时应问：搜索图、局部速度和实际碰撞，哪一层认为这条路可行？

部分路径也需要清楚地呈现。若目标位于不可达区域，某些接口可以返回到最近可达点的路线。角色走到墙边停下，可能是在执行部分路径，而非完整路径中途失灵。任务逻辑应检查到达状态，不能只凭“返回了几个路径点”就宣布目的地可达。

## 同一扇门 可以有两张地图

设小机器人半径0.4米，大机器人半径0.6米。对一米门洞，小机器人的中心可沿中间窄带穿过，大机器人对应的两侧禁区已经重叠。为两者使用不同代理配置或分别烘焙，并不是复制了无用数据，而是在表达不同的几何问题。

若大机器人能侧身，圆形近似又可能过于保守；需要考虑方向的配置空间，复杂度随之增加。若它从来不能侧身，强行保留一条视觉上存在的缝就没有价值。调试导航时，先把角色画成实际碰撞形状放进门里，往往比换一个更聪明的最短路算法更快找到原因。
