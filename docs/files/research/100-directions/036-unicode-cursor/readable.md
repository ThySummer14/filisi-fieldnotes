# 删除键眼里的一个字

“é”和“é”看起来可以完全一样。第一个字符串包含一个码点，第二个是字母e再加一个组合重音。在本次 Python 实验中，它们分别占2和3个UTF-8字节，码点数分别为1和2。倘若表单把“最多十个字”实现为字节长度限制，两个外观相同的名字就可能得到不同待遇。

这不是只与罕见文字有关的边角问题。👩🏽‍💻由女性、肤色修饰符、零宽连接符和电脑四个码点组成，本次计数为15个UTF-8字节、7个UTF-16代码单元。🇨🇳由两个区域指示符组成，计数为8个UTF-8字节、4个UTF-16代码单元。这里测量的是字符串表示，未测试某款字体是否能把它们画成一个图形。

## 光标不能照着存储单位走

字节是编码后的存储单位。码点是Unicode编码空间里的位置。UTF-16的代码单元固定16位，补充平面上的字符需要一对代理项；因此“向后移动一个代码单元”甚至可能停到一个代理对中间。[Unicode核心规范](https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-3/)对这些术语有严格区分。

文字编辑还需要更接近阅读经验的单位。Unicode的扩展字素簇规则把某些相邻码点归成一组，例如基础字母与组合标记，以及符合规则的表情连接序列。对于普通文本框，把字素簇边界作为光标移动、截断和选择的默认依据，通常比逐码点处理合理。

但字素簇仍然是默认算法的结果。它不会替所有语言、字体和编辑任务定义唯一正确的删除动作。[UAX #29](https://www.unicode.org/reports/tr29/)允许明确记录的定制，也提醒文字本身不总能提供足够信息来完全匹配人的感知。一个专门修改变音符号的语言学编辑器，可能希望先删除重音再删除字母；日常聊天输入框则可能选择一次删除整个组合。产品需要决定的是操作语义，不能把库的返回值直接包装成“人眼看到的一个字”的绝对定义。

最危险的半成品，是先用正确的分段器数出字素簇，再用原来的字符串索引去切割。两边的单位不同，漂亮的计数仍然会制造断裂字符。ECMAScript的 `Intl.Segmenter` 提供grapheme、word和sentence粒度，但其返回的索引仍使用字符串代码单元位置。这个设计让结果能接上JavaScript原生切片，也要求调用者知道索引究竟属于哪一种单位。[ECMA-402的分段器规范](https://tc39.es/ecma402/#segmenter-objects)明确写出了这层接口关系。

## 统一表示也不能代替分段

把两个é归一化为NFC，本次实验确实得到相同的单码点表示。因此在需要规范等价比较的场景中，归一化能减少同字不同写法带来的重复记录。然而，那个四码点的程序员表情在NFC之后仍然保留四个码点。归一化解决等价表示，分段解决操作边界，不能用前者替代后者。

[UAX #15](https://www.unicode.org/reports/tr15/)还区分规范等价与兼容等价。兼容归一化可能抹去某些排版或语义区分，所以不能因为希望搜索更宽松，就无条件改写用户保存的原文。一个可解释的设计是保留原文，另存用于搜索的规范化键，并明确该键不能作为原文的无损替代。

这会影响错误提示的措辞。数据库列的字节上限是在控制存储；产品的“昵称长度”通常在控制阅读负担。两个限制可以同时存在，但用户应当看到自己能理解的计数。若后端最多接收一定数量的字节，前端只承诺一定数量的字素簇，又没有检查编码后的大小，仍然会在少数输入上提交失败。字素簇内部可以带多个组合字符，不能假设每簇存在一个很小的固定字节数。

## 给编辑器准备一组会失败的输入

测试只放“hello”和“你好”，很难发现索引单位混用。更有用的输入包括预组合与分解的é、带肤色的连接表情、区域指示符、以及文字首尾的组合标记。对每个输入分别执行删除、左右移动、选中后替换、达到长度上限后的粘贴。检查结果是否仍为合法编码，同时确认被删掉的范围与产品约定一致。

还有版本问题。分段器依赖Unicode属性与规则，运行时更新后可能认识更多序列。若客户端和服务器独立计数，应记录使用的规则版本，至少让测试样本覆盖已支持的字符。这里无需把所有文本系统冻结在某一版Unicode；需要保证同一次输入不会在前端被接受、后端又按另一套“一个字”拒绝。

面向普通文本的编辑器应优先把光标和删除行为建立在经过测试的字素边界上。源码编辑器、音标工具或字符检查器可以提供更细的操作，但要让使用者看见这种选择。字符越复杂，按钮的标签越不该靠一个含糊的length函数解释。

接口命名也能降低混用的概率。把字段叫作“字节偏移”或“UTF-16索引”，比统一叫position多传递了一层约束。如果渲染引擎、搜索接口和协作协议采用不同单位，转换应集中在明确的边界，不能散落在事件处理函数里。否则文本改动后，旧索引即使数值没有越界，也可能指向完全不同的字。

搜索高亮是一个容易观察的例子：归一化后的检索文本与原文可能长度不同，搜索结果的区间不能未经映射就画回原文。保留位置对应关系，或在原文边界上重新匹配，才有机会让高亮和删除覆盖相同的内容。
