# 源代码一样 为什么打包文件还是不同

把同一份六字节文本hello加换行装进ZIP，文件名和压缩方式保持不变，只把条目时间从2020年1月1日改为1月2日，归档的SHA-256就改变了。再用第一次的时间重建，哈希恢复一致。本次使用Python标准库和不压缩的ZIP格式完成这个小实验，差异来自元数据，正文没有改动。

这个例子不涉及编译器，却已经说明“源文件一样”远远不够。产物可以包含时间、文件排序、路径、工具版本、地区设置，甚至构建脚本从网络读取的内容。只固定仓库提交，仍可能留下许多输入在仓库之外。

[Reproducible Builds的定义](https://reproducible-builds.org/docs/definition/)要求相同源代码、构建环境和指令能让不同参与者重建逐位相同的指定产物。环境并非附带说明，而是定义的一部分；哪些文件属于要比对的产物，也需要明确。编译日志不同不必使可执行文件的可复现性失败，反过来只比较程序运行输出也不足以证明二进制相同。

## 先找出哪个字节变了

两次哈希不同，只说明产物不一致，不说明原因。直接重跑十次，希望偶尔匹配，通常不如拆开归档检查元数据。若变化集中在时间字段，处理时钟输入；若顺序变化，检查目录遍历与集合迭代；若出现不同的绝对路径，追踪调试信息与生成代码。

[SOURCE_DATE_EPOCH约定](https://reproducible-builds.org/docs/source-date-epoch/)给构建工具提供一个稳定时间来源，通常反映源代码的最后修改时刻。它只有在相关工具确实遵守时才生效。设一个环境变量，不会自动改写所有归档格式、外部编译器和自定义脚本。

也不要为了哈希一致随意抹掉有意义的信息。软件版本、许可证信息和用于调试的必要映射，可能仍需保留。可以固定或映射构建路径，把时间改成可重复来源，而非粗暴删除所有元数据。修复后还要验证产物仍然可用，签名、安装与调试流程没有被破坏。

## 容器不是环境的全部

[Bazel的hermeticity文档](https://bazel.build/basics/hermeticity)把隔离构建与外部环境依赖联系起来。系统上的工具、绝对路径、生成时间等都可能成为非预期输入。一个构建动作若只读取已声明的内容和工具，结果才更容易缓存与重现。

把脚本放进容器能减少差异，但容器里若仍然下载“最新版”依赖，或读取挂载目录中的未声明文件，输入仍在变化。镜像标签也可能指向不同内容；需要记录可定位的版本或内容标识。网络访问是否允许、依赖能否离线取得，都应进入构建说明，而不是留给执行者猜。

本次ZIP实验刻意控制了正文、文件名、压缩方式与时间，所以能把差异归因到一个变量。真实项目可以采用同样的缩小方法：先在相同环境重复构建，再改变构建路径、时区、语言环境或并行度。每次只改变已知条件，更容易定位隐藏输入。一次成功匹配只能覆盖那一组条件，不能证明所有平台都逐位一致。

## 两次都一样 也可能两次都错

Ken Thompson的[Reflections on Trusting Trust](https://www.cs.cmu.edu/~rdriley/487/papers/Thompson_1984_ReflectionsonTrustingTrust.pdf)用编译器自举说明，信任链不能只停在眼前看到的源代码。一个被污染的工具链可能稳定地产生带问题的产物。重复运行同一套工具，并不会自动暴露这类一致的错误。

因此，可复现性提供的是对照能力：独立参与者能检查发布产物是否来自约定输入与流程。它不证明程序没有漏洞，不证明源代码值得信任，也不保证编译器本身正确。若要降低工具链污染风险，需要更进一步的独立性与验证方法，不能把“哈希一致”当作完整安全证书。

独立构建也不应只复制发布者的整个不透明环境后照着运行。环境可以被记录、检查与重建，验证者才有机会发现异常依赖。实际采用多大程度的独立性，要与威胁模型和成本相匹配；小工具和高风险基础设施未必需要同样流程。

## 给发布留下能重走的路径

一个可操作的发布记录应包含源代码修订、工具链版本、依赖锁定信息、构建命令与被比对产物列表。需要外部输入时，应说明来源和内容标识。若某部分暂时不可复现，指出具体文件与差异原因，比笼统宣称“基本可复现”更便于后续修复。

测试还应区分清洁构建与缓存构建。两次都命中同一份旧缓存，得到相同哈希并没有检验重建能力。至少有一次应从受控的干净工作区真正执行过程，并核查依赖是否来自记录的来源。构建时间若下降，也不能不看日志就认定增量机制正确。

对普通项目，先让相同提交在不同目录里生成相同产物，是一个有价值的起点。随后逐步扩大被扰动的环境变量，记录仍然不能固定的因素。这里最有用的产出不是一个永久亮绿的徽章，而是一份别人能照着重建、失败时能定位到输入差异的说明。

回到那两个ZIP文件，读取正文会得到同一个hello，二进制比较却会失败。这两种检查都正确，只是在回答不同问题。发布流程应先决定需要相同的是行为、文件内容还是整个归档字节，再为那个承诺建立证据。
