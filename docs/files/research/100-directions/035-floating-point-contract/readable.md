# 0.1加0.2之后 系统究竟答应了什么

在 Python 3.12.14 中运行 `0.1 + 0.2 == 0.3`，结果是假。把两边打印成一位小数，却都得到0.3。显示层让它们看起来相等，比较运算仍然能分出差别。这个小实验没有说明计算机不可靠；它暴露出程序里存在两套不同的要求：数值要足够接近，还是必须完全相同。

0.1在十进制里很短，在二进制里却是无限循环小数。常见的 binary64 用有限位数保存它，只能选一个附近的数。Python 官方教程把这个近似写成一个精确分数：3602879701896397除以2的55次方。打印0.1是把这个值转换成便于阅读、又能读回同一浮点值的字符串，并没有把底层的数改成十分之一。[表示误差的解释](https://docs.python.org/3/tutorial/floatingpoint.html)也说明，先调用 round 再相加，不能普遍解决问题。

## 一个单位为什么会消失

更能影响计算的是不同数量级相加。本次环境中的 `(1e16 + 1) - 1e16` 得到0.0，数学上的答案是1。中间那次加法已经把小量丢掉，后面的减法没有办法把它找回来。对同一组输入调用 `math.fsum([1e16, 1, -1e16])` 得到1.0。这是三个合成输入上的结果，不是性能测试，也不能推出 fsum 可以修复任意算法。

Goldberg的论文区分了几种误差来源。其中一个值得记住的细节：两个接近的量相减时，减法自身可能是精确的，糟糕的相对误差来自它把前面计算留下的误差暴露了出来。若两个很大的估计数相减，只剩很小的差，之前看似无关紧要的小误差就可能占据结果的大部分。[论文中的消去分析](https://docs.oracle.com/cd/E19957-01/806-3568/ncg_goldberg.html)因此讨论改写公式，而非只增加显示的小数位数。

这也解释了为什么“误差只有十几位以后才出现”不能独立判断风险。若结果用于画一个位置相近的点，误差可能无关紧要；若它决定下一步走哪个分支，比较边界就会放大后果。把本应为零的残差交给 `x > 0`，可能改变程序流程。这里的风险判断是由比较规则推导出来的，不是某个产品事故的记录。

## 近似相等不是一种身份

Python的 `math.isclose` 同时支持相对容差和绝对容差。相对容差按参与比较的数值尺度放大；绝对容差为接近零的比较提供固定底线。官方给出的判据是差的绝对值不超过这两种界限中的较大者。若拿一个非零的小量与零比较，只有默认相对容差通常仍会失败，因为容差也随这个小量一起缩小。[接口定义](https://docs.python.org/3/library/math.html#math.isclose)把这个边界写得很明确。

容差应该来自问题。长度以米计时，允许误差一毫米可以写成0.001；把单位换成毫米，阈值也应一起换。随手写一个 `1e-6`，并没有说明它代表测量误差、显示分辨率，还是算法允许的残差。

还有一个常被忽略的限制。假设“足够接近”定义为相差不超过1，0与0.75接近，0.75与1.5接近，0与1.5却不接近。这个关系不具备传递性。这个反例只需要算术，不依赖浮点实现。因而不能直接把近似相等当作数据库唯一键、集合去重或对象身份的通用替代品。业务确实要按网格合并位置时，先定义离散网格及边界归属，会比临时更改相等关系更容易解释。

## 换成十进制以后仍有决定要做

若需求是精确表达有限位十进制金额，Decimal或以最小单位保存的整数通常更合适。入口就要保留十进制意图：本次实测 `Decimal('0.1') + Decimal('0.2')` 得到0.3，而 `Decimal(0.1)` 会忠实保留传入浮点数的长尾。先损失信息，再换类型，不会恢复原始输入。

[Decimal文档](https://docs.python.org/3/library/decimal.html)还展示了精度上下文和舍入模式。十进制并不等于所有运算都精确：1除以7仍然不能用有限位十进制写完。整数分币也没有替人决定一分钱怎样分给三个人。需要约定余数分配、舍入时机，以及多行分别舍入和合计后舍入哪一种才符合规则。

对测量与物理计算，保留浮点数并选择稳定算法往往更合理；为追求“完全没有小数误差”而全面换成Decimal，可能只换来成本并留下同样的建模问题。应当先写下一个会让程序判错的具体条件，例如余额必须守恒到分，或距离比较允许一毫米，再决定数据类型和测试断言。测试里留下那个边界，比把0.30000000000000004格式化掉更有用。

还有一条测试规则容易写反：不要把所有精确比较机械地换成近似比较。状态枚举、计数器以及经过明确定义的量化结果，仍然可以要求精确相等。测量结果可以带误差，不代表系统里每个字段都应该模糊。反过来，容差通过了也不等于算法正确；把毫米误写为米的程序，若测试数据全是零，同样可能过关。

可以为一个计算保留两套断言。第一套检查数值残差是否落在有物理含义的范围内；第二套检查结构约束，比如条目总数不变、分配后的整数总额等于输入总额、排序结果是否单调。前者允许近似，后者守住不能损失的规则。再加上接近零、大量级与小量级混合、正负抵消的输入，测试才能接触到真正脆弱的地方。
